# 域名、网站 ICP、App 与公安联网备案

[返回首页](../README.md) · [全部问题](README.md) · [踩坑索引](../cases/README.md)

## 先把办理对象列出来

| 对象 | 先整理什么 | 接着处理什么 |
| --- | --- | --- |
| 网站 | 主体、域名、接入服务与真实业务说明 | 向接入服务商提交 ICP 备案，按反馈补件和确认结果 |
| App | 主体、App 名称、应用标识、证书特征及实际联网用途 | 按对应办理渠道提交 App 备案资料，核对结果与产品展示 |
| 公安联网备案 | 已有备案与实际开通信息、负责人及安全管理资料 | 按公安平台当前指引申请，确认结果与展示要求 |

每一项单独记申请编号和结果。云服务促销价格、个人一次办理耗时，都不能替你判断手续是否完成。

<a id="q019"></a>

## 买域名和服务器之前，先确认哪些备案条件？

先确认业务部署地区、接入服务商是否支持你的备案、产品形态和主体信息是否匹配。再比较域名首年与续费价格、服务器长期价格及实际资源需求。

“最便宜后缀”和“首年特价服务器”并不能替你完成这些判断，也没有一组对所有人一直有效的价格。

<a id="q020"></a>

## 网站 ICP 备案、App 备案、公安联网备案有什么区别？

先按办理对象拆开：网站 ICP 对应网站接入和登记信息；App 备案对应具体 App；公安联网备案是另一套办理流程。不要把一个后台的通过提示当作所有手续都完成。

可以建一张表，逐项记录主体、网站或 App 名称、域名或应用标识、受理渠道、结果及展示位置。

<a id="q021"></a>

## 同一家公司做多个网站，可以直接复制同一个页脚号吗？

我的三个网站分别对应不同的备案序号。两份产品官网曾共用静态页面，所以后来按访问域名展示对应的信息。

实际部署时把每个网站与自己的核准记录逐一对上，再检查页脚链接。不要从“公司一样”推导出所有网站都用同一个完整号码。

<a id="q022"></a>

## 网站备案号能不能直接填到 App 或另一款产品里？

合唱练习的 App 备案号末尾是 -4A，公司网站则有 -1、-2、-3。后来做聆思时，不能直接拿合唱练习的记录代替新 App 的信息。

填写前核对应用名称、主体、应用标识和证书特征。区分网站和 App，也区分同一主体下的不同产品。

<a id="q023"></a>

## iOS 备案材料里的证书指纹，应该取哪一种？

我处理 iOS 备案资料时对应的是 SHA-1 特征信息。证书本身、证书序列号、SHA-1 和 SHA-256 不是同一项。

操作时先看当前表单字段与接入商说明，确认对应证书，再导出要求的特征值。不要把另一个平台要求的摘要算法直接抄过来。

<a id="q024"></a>

## ICP 已经办完，公安联网备案接下来从哪里办？

通过全国互联网安全管理服务平台核对办理对象和材料，接着处理公安联网备案。阿里云当前指南说明，应在网站或 App 开通之日起 30 日内提交申请；网站通过后还要完成相应信息展示。[查看办理指南](https://help.aliyun.com/zh/icp-filing/basic-icp-service/the-public-security-network-for-record-and-cancellation)。

别只在网站底部放一个 ICP 号就结束检查。

<a id="q025"></a>

## App 公安备案显示通过，却找不到号码，该怎么查？

我在七月发帖问过这个问题。此前六月的开发记录仍是 App 公安备案办理中，后面我看到通过却没找到预期号码，当时没有查清原因。

遇到同样情况，保留申请编号和页面状态，确认自己查看的是 App 记录，再向受理方问清结果与展示要求。不要自行认定是同步延迟，更不要借用网站的公安号。

<a id="q026"></a>

## 本地处理、没有自建后端的 App，也会遇到备案或分发问题吗？

会，我的聆思就遇到过。App 已发布，香港可下载，中国大陆却被缺少 ICP 信息挡住。后来向 Apple 解释本地处理方式、无自建后端及模型下载事实，并补交盖章申请函。

这是 Apple 对该产品大陆分发的个案处理。需要处理同类问题时，先读地区不可用原因再联系支持；它不能代替政府 App 备案或公安联网备案结论。

<a id="q027"></a>

## 备案通过后，还要在产品里补哪些信息？

按自己的核准结果和展示要求，检查网站页脚、App 的关于或个人页面、用户协议和隐私政策。我的合唱练习在备案通过后，就补了个人页和法律页面的 App 备案展示。

没有拿到某项号码时，别先填占位号，更不要填其他产品的号码。换域名、换主体或变更产品信息时，再核对需要更新的记录。
