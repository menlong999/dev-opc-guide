# 失业以后，先想清楚做什么

[返回首页](../README.md) · [全部问题](README.md) · [踩坑索引](../cases/README.md)

<a id="q001"></a>

## 大龄程序员失业后，做 OPC 到底要先解决什么问题？

先写清楚：为谁解决哪个问题，对方现在怎么处理，为什么愿意付钱，你能用多少钱和多长时间去验证。把求职、生活开支和产品试错放在同一张时间表里，再决定投入范围。

我最深的感受是：代码写出来以后，还有公司、备案、收款、上架和售后。一人公司意味着这些工作也落到自己身上。

<a id="q002"></a>

## 应该先注册公司，还是先找到真实需求？

如果还没有明确客户，先访谈、演示和验证需求，避免为了拥有一家公司先产生长期支出。需要签企业合同、申请平台主体能力时，再根据具体要求安排注册。

先列出目标渠道所需主体和材料，可以提前发现哪些手续会挡住上线。不要等产品做完才第一次打开申请表。

<a id="q003"></a>

## 做 To C（面向个人用户），怎么判断小众需求值不值得做？

看具体使用场景和已经发生的需求：谁反复遇到问题，现有替代方式有什么成本，愿不愿意试用、反馈或付款。先验证一个能完整解决问题的场景。

我的合唱产品来自真实用户需求，但有需求之后，仍然遇到分发、版权材料和支付申请。需求验证和上线条件，两件事都要做。

<a id="q004"></a>

## 做 To B（面向企业客户），怎么让客户愿意把项目交给一个人？

把承诺变成客户能核对的东西：业务理解、演示、交付范围、里程碑、验收方式和维护安排。先做范围明确的小项目，让客户知道买到什么、何时拿到、出了问题找谁。

不要用一个人的身份承诺全天候团队服务。把自己能承担的工作和需要客户配合的条件提前写进报价与合同。

<a id="q005"></a>

## 做 App、网站、AI 工具、Skill（技能包），第一步怎么选？

按用户使用场景选交付形式，再看分发与收款成本。手机原生能力强的需求考虑 App；需要快速演示和持续更新的需求可以先评估网页；依赖智能体宿主的工作流，则要确认宿主能加载什么、如何安装和更新。

先选一条能交付价值的路径。同时开多种渠道，会同时增加账号、审核、支付和维护工作。

<a id="q006"></a>

## 一个人有必要从第一天就做 iOS、Android 和网页吗？

先比较目标用户在哪、哪条路径能完整交付、哪条路径已经具备申请条件，再决定先做哪端。我遇到 Android 分发和移动应用支付互相制约时，就考虑过先走 iOS。

这是当时的取舍；不能仅凭某一端开发方便，就认为它一定适合你的用户。

<a id="q007"></a>

## 预算有限时，应该先算哪些持续支出？

把生活预算和经营预算分开。经营预算至少逐项问清：财税服务、银行账户、域名与服务器续费、开发者账号、平台认证、模型调用、设备测试和售后。

首年优惠价和长期续费价分开记，注册时没花钱的项目也要单列。不要把一次低价开通当作长期成本。

<a id="q008"></a>

## 一人公司有哪些事情能用 AI 帮忙，哪些必须自己确认？

AI 可以帮你整理申请清单、读驳回说明、生成材料草稿和检查页面。但公司全称、业务形态、金额、签名算法、申请结果和审核版本，必须回到原件、接口文档或实际后台确认。

我就遇到过审核说明比送审版本功能写得更靠前的问题。AI 帮你写得快，也需要你对提交内容负责。
